Developer guide

Build a sample app

Start with a working reference app, then replace its domain. A Blueprint owns application composition and behavior; components render data and emit intents; the host authorizes and executes external work.

Start with Finbook

Finbook is a small finance report explorer with a Blueprint, app-owned components, a React host, and a SQLite-backed MCP server. Its GIK libraries, including gik-components, come from npm. It does not need Studio or a sibling Components build.

Browse the complete reference app · Setup and extraction guide

With Node.js 24 installed, run:

git clone https://github.com/nsreehari/gik-samples.git
cd gik-samples/apps/finbook
npm install --no-audit --no-fund
npm run dev

Open http://127.0.0.1:5176/finbook/. The command starts the local browser host and the MCP server.

This Pages site is static: it cannot run Finbook's Node/SQLite backend. Keep the local server on loopback. Preserve the app-contained XYFlow archives when extracting the directory; the app README explains the split.

From reference app to your own application

1. Define responsibilities as Cells

Start from the user outcome, not the page layout. Finbook separates selection from report exploration into finbook-selector and finbook-explorer. Declare the input/output ports that connect those responsibilities.

Read the Finbook Blueprint

2. Declare data access and event behavior

Declare service operations and bounded Cell sources, derive outputs with compute, and handle declared events. Settled source results are read through fetched_sources. Reduction produces state and effects; external work is performed by the host, not inside a component.

Blueprint contracts and source semantics

3. Choose presentation without changing meaning

Attach named Cell views to presentation slots. Register only the component providers you use, including any app-owned finance or domain catalog. Declare both service and projection lowering axes, even when an axis has no recipes.

Inspect the app-owned components · Component providers and authoring tools

4. Compose a small host

Mount the Blueprint with BlueprintHost, explicit projection providers, and a service host. Keep endpoint authorization, credential resolution, and execution authority in this trusted boundary. Never put literal secrets in Blueprint JSON.

Follow Finbook's host wiring · React hosting API

5. Replace the domain behind stable contracts

Implement your data access, calculations, and integrations behind declared operations. Finbook keeps its tool schemas, finance calculations, and SQLite adapter together. A hosted backend needs authentication and shared durable storage; a function's local SQLite file is not a production database.

Read the server implementation · Persistence obligations

6. Validate the complete app independently

From the Finbook app directory, run npm run check. It typechecks, validates the Blueprint, builds the browser, and runs app/domain/server tests. Keep tests for your public port, event, and service-result shapes.
