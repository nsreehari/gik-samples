One mental model, distinct responsibilities

Blueprint state + event -> new state + effects
Host executes authorized effects -> results or new events
Blueprint and Cell
A Blueprint composes semantic Cells, ports, events, services, and presentation. A Cell's meaning is independent of the component used to display it.
Components and projection
Components render declared props and emit intents. Local UI mechanics stay local; cross-Cell state and workflow belong to the Blueprint. Register providers explicitly.
Bounded sources
A source performs a bounded request and settles a result. Expressions read settled data through fetched_sources.<id>.
Senses
A Sense declares continuing observation intent. The host reconciles committed bindings and delivers discrete Signals through durable ingress; a normal source fetch or generic React mount does not establish an observer.
Purpose-bearing Cells
Use a DPP only for an enduring responsibility to create value for identifiable beneficiaries within explicit boundaries. Being an agent, conversation, or stateful function is not sufficient. The full dpp.manifest expresses that reference frame; context query/ingest supports the purpose, not the other way around. Participation uses ordinary Cell inputs, outputs, and effects, without a mandatory reasoning loop, special component, automatic scheduler, or permission grant.

For exact contracts, use the Blueprint README, Sense guide, and DPP guide. This site explains how the samples use them; it does not redefine their APIs.

Choose a package by the job it does

Author and host applications
Start with gik-blueprint for definitions and materialization, and gik-react for React hosting.
Render declared UI
gik-components supplies explicit primitive, semantic, Fluent, and opt-in domain catalogs. Its README owns consumer APIs; Storybook shows individual components.
Run durably or integrate agents
Use the core package map to choose kernel, evaluators, durable runtime, faces, transports, lifecycle, and proposal-host boundaries. Public packages and private workspaces are distinguished there.
Download a verified release
Package downloads contains the released Components archive and ten core GIK archives, with a manifest and SHA-256 checksums. It is not an npm registry. Consumer manifests and the generated manifest own version information, not a second version table on this site.

Know what runs where

This static site

Pages serves Studio, this documentation, Storybook, bootstrap artifacts, and package downloads. Selected Blueprints use ?b=<id>. Existing Studio and scenario URLs remain unchanged.

Your trusted host

Hosts own endpoint authorization, credential resolution, effect execution, observers, errors, and shutdown. Blueprint services own concrete non-secret endpoints and opaque credentialRef values. Never commit literal secrets.

Local tools and provisioning

The optional loopback MCP companion supplies reviewed workspace execution and provisioning. You can export a portable plan without granting execution authority. Pair only an approved origin and workspace.

Open provisioning · Install and pair the companion

For standalone or hosted Finbook, use its app README and persistence contract. A local SQLite file is not shared production storage. Hosting your own backend also requires an authentication and endpoint-authorization policy.

Develop, validate, and maintain

Use Node.js 24. Studio develops against local Components; standalone Finbook consumes the npm package. Follow the validation sequence and contribution rules. The release guide owns publication and Pages refresh behavior.
